# بررسی‌های باز

هرچه در این دور بررسی **مستقیماً تست نشد** یا نتیجه‌اش قطعی نبود، اینجا
فهرست شده تا به‌اشتباه «حل‌شده» تلقی نشود.

## دسترسی Vercel Dashboard

- **چرا باز است:** این بررسی هیچ توکن/دسترسی API به پروژهٔ Vercel
  نداشت. فقط از طریق درخواست HTTP عمومی به `www.dofixo.ir` کار شد.
- **چه باید بررسی شود:** Project → Settings → Functions (آیا واقعاً صفر
  Function وجود دارد؟)، → Domains (قانون دقیق ریدایرکت apex↔www)، →
  هر Rewrite/Middleware تعریف‌شده‌ای که در کد دیده نمی‌شود.
- **چه کسی باید انجام دهد:** فردی با دسترسی مالک/عضو تیم پروژه در Vercel.

## ~~نسخهٔ `@astrojs/vercel`~~ — حل شد (۲۰۲۶-۱۱-۱۳)

بررسی مستقیم `npm view @astrojs/vercel peerDependencies` نشان داد
آخرین نسخه (`11.0.21`) دقیقاً `{ astro: "^7.0.0" }` می‌خواهد — کاملاً
سازگار با `astro@7.3.5` این ریپو. نصب و `pnpm build` محلی بدون خطای
peer dependency انجام شد. جزئیات در `decisions.md` (D1، D2).

## ~~محدودسازی نرخ (Rate Limiting) پایدار~~ — تصمیم گرفته شد (۲۰۲۶-۱۱-۱۳)

تحلیل فنی اولیه پابرجاست (in-memory بین instanceهای Vercel مشترک
نیست)، اما مالک پروژه تصمیم گرفت فعلاً فقط به یک فیلد honeypot
بسنده شود، چون حجم ترافیک این فرم بسیار کم است و ایمیل کانال فرعی
است. جزئیات در `decisions.md` (D3). **اگر اسپم واقعی دیده شد، این
تصمیم باید بازبینی شود.**

## ~~Core Web Vitals و Lighthouse~~ — تا حدی حل شد (۲۰۲۶-۱۱-۱۳)

Lighthouse محلی روی خروجی واقعی build اجرا شد (جزئیات در `roadmap.md`
T5.1). یافته‌ی مربوط به حجم تصویر صفحه‌ی اصلی واقعی و تکرارپذیر بود و
رفع شد. **اما عدد LCP خودِ این sandbox بین اجراهای پشت‌سرهم نوسان زیاد
داشت (۴.۷ تا ۶.۴ ثانیه روی دقیقاً یک build)** — یعنی قابل‌اتکا نیست.

**هنوز باز:** دادهٔ میدانی واقعی (CrUX) یا یک اجرای PageSpeed Insights
رسمی (pagespeed.web.dev) روی `www.dofixo.ir` — این‌ها را فقط کسی با
مرورگر واقعی و دسترسی به اینترنت عمومی (نه این sandbox) می‌تواند ثبت
کند.
