# بررسی‌های باز

هرچه در این دور بررسی **مستقیماً تست نشد** یا نتیجه‌اش قطعی نبود، اینجا
فهرست شده تا به‌اشتباه «حل‌شده» تلقی نشود.

## دسترسی Vercel Dashboard

- **چرا باز است:** این بررسی هیچ توکن/دسترسی API به پروژهٔ Vercel
  نداشت. فقط از طریق درخواست HTTP عمومی به `www.dofixo.ir` کار شد.
- **چه باید بررسی شود:** Project → Settings → Functions (آیا واقعاً صفر
  Function وجود دارد؟)، → Domains (قانون دقیق ریدایرکت apex↔www)، →
  هر Rewrite/Middleware تعریف‌شده‌ای که در کد دیده نمی‌شود.
- **چه کسی باید انجام دهد:** فردی با دسترسی مالک/عضو تیم پروژه در Vercel.

## نسخهٔ `@astrojs/vercel`

- **چرا باز است:** جست‌وجوی وب نشان داد `@astrojs/vercel@10.0.6` با
  `peerDependencies: { "astro": "^6.0.0" }` منتشر شده (مارس ۲۰۲۶)، و
  نسخهٔ ۱۱.x هم وجود دارد (ژوئن–ژوئیهٔ ۲۰۲۶) اما `peerDependencies`ی آن
  برای Astro 7 از منابع در دسترس تأیید نشد. صفحات رسمی
  `docs.astro.build` از شبکهٔ این بررسی در دسترس نبودند (DNS/شبکه
  مسدود).
- **چه باید بررسی شود:** قبل از هر نصب واقعی، فیلد `peerDependencies`
  در `package.json` آخرین نسخهٔ `@astrojs/vercel` روی npm/GitHub
  مستقیماً بررسی شود تا سازگاری با Astro `7.3.5` قطعی شود — **به هیچ
  مثال قدیمی `output: 'hybrid'` اعتماد نکنید**؛ مدل فعلی Astro (از
  نسخهٔ ۵ به بعد) `output: 'static'` + `export const prerender = false`
  در فایل endpoint است، نه یک حالت جداگانه به نام hybrid.
- **ریسک اگر نادیده گرفته شود:** نصب نسخهٔ ناسازگار می‌تواند build را
  در Vercel بشکند یا رفتار صفحات استاتیک موجود را تغییر دهد.

## محدودسازی نرخ (Rate Limiting) پایدار

- **چرا in-memory کافی نیست:** هر فراخوانی Function در Vercel می‌تواند
  روی یک instance کاملاً تازه (cold start) یا یک instance موازی دیگر در
  منطقهٔ جغرافیایی دیگر اجرا شود؛ متغیر حافظه‌ای بین این instanceها
  مشترک نیست و با هر cold start از صفر شروع می‌شود — یعنی شمارندهٔ
  in-memory عملاً نمی‌تواند «تعداد درخواست در بازهٔ زمانی» را به‌درستی
  محدود کند.
- **راه‌حل پیشنهادی (نیازمند تصمیم تیم، نه اجراشده):** یک فروشگاه
  کلید-مقدار خارجی و پایدار که از همهٔ instanceها در دسترس باشد (مثل
  Vercel KV یا یک سرویس Redis مدیریت‌شده). انتخاب دقیق سرویس در
  `decisions.md` ثبت می‌شود، نه اینجا.

## نیازمندی‌های سرویس ایمیل برای گیرندهٔ Gmail

- **چرا باز است:** هیچ سرویس ایمیلی در این بررسی انتخاب یا تأیید نشد.
  ارسال به یک آدرس Gmail از یک سرویس ایمیل تراکنشی معمولاً نیاز به
  پیکربندی SPF/DKIM روی دامنهٔ فرستنده دارد تا در پوشهٔ Spam نیفتد —
  این نیازمندی **به ازای هر سرویس فرق می‌کند** و تأیید نشد.
- **چه باید بررسی شود:** مستندات سرویس انتخابی (پس از تصمیم تیم) برای
  محدودیت پلن رایگان، نیاز به تأیید دامنه، و نرخ تحویل به Gmail.
