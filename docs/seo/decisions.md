## D1 — معماری فرم تماس: Vercel Serverless Function

- **وضعیت:** Approved و **اجراشده** (۲۰۲۶-۱۱-۱۳).
- **گزینه‌های بررسی‌شده:** (A) Vercel Serverless Function روی همین
  ریپو، (B) بک‌اند مجزا روی میزبان دیگر، (C) سرویس بیرونی پردازش فرم
  (Formspree و مشابه).
- **تصمیم:** گزینهٔ A.
- **استدلال:** این ریپو از قبل روی Vercel با Astro مستقر است؛ افزودن
  یک Function تنها به یک فایل endpoint و یک آداپتور نیاز دارد، بدون
  میزبان/CORS/دیپلوی جدید (گزینه B) و بدون وابستگی به کنترل‌پنل یک
  سرویس بیرونی برای دادهٔ Lead (گزینه C).
- **پیش‌شرط قبل از اجرا (رفع شد):** نسخهٔ `@astrojs/vercel@11.0.21`
  مستقیماً روی npm بررسی شد — `peerDependencies: { astro: "^7.0.0" }`
  — کاملاً سازگار با `astro@7.3.5` نصب‌شده در این ریپو. نصب و build
  محلی بدون خطای peer dependency انجام شد.
- **فایل‌ها:** `astro.config.mjs` (افزودن `adapter: vercel()`)،
  `package.json`/`pnpm-lock.yaml` (وابستگی جدید)،
  `src/pages/api/contact.ts` (مسیر جدید).

## D2 — مدل رندر: نگه‌داشتن `output: 'static'` + `prerender = false` روی یک فایل

- **وضعیت:** Approved و **اجراشده** (۲۰۲۶-۱۱-۱۳).
- **گزینه‌های بررسی‌شده:** تنظیم سراسری `output: 'server'` در برابر
  نگه‌داشتن `output: 'static'` (پیش‌فرض فعلی، بدون تغییر) و اضافه‌کردن
  `export const prerender = false` فقط به فایل endpoint جدید.
- **تصمیم:** گزینهٔ دوم.
- **استدلال:** تقریباً تمام سایت (بیش از ۶۰ صفحه) باید استاتیک بماند؛
  تغییر سراسری به `output: 'server'` یعنی همهٔ صفحات پیش‌فرض
  on-demand می‌شوند مگر صراحتاً `prerender = true` بگیرند — ریسک و حجم
  تغییر بسیار بیشتر از نیاز واقعی (یک endpoint) است.
- **تأیید عملی:** `pnpm build` محلی تأیید کرد همهٔ صفحات همچنان در
  `dist/client/**/index.html` به‌صورت کاملاً استاتیک ساخته می‌شوند؛
  فقط `/api/contact` در `.vercel/output/functions/_render.func`
  به‌صورت Serverless Function درآمده.
- **⚠️ اثر جانبی کشف‌شده و رفع‌شده:** افزودن آداپتور، ساختار خروجی
  build را تغییر می‌دهد: به‌جای `dist/` تخت، خروجی استاتیک حالا در
  `dist/client/` است (و `dist/server/` فقط رندرر SSR را دارد).
  `scripts/check-site.mjs` با فرض قدیمی (`dist/` تخت) می‌شکست؛
  مسیر `DIST` در آن اسکریپت به `dist/client` اصلاح شد — **بدون بای‌پس
  کردن بررسی**، طبق قاعدهٔ `CLAUDE.md`.

## D3 — محدودسازی نرخ: فروشگاه کلید-مقدار خارجی به‌جای حافظهٔ داخلی Function

- **وضعیت:** Approved — با تصمیم مالک پروژه در D4، این بند **عمداً کنار
  گذاشته شد**، نه فراموش شد.
- **استدلال اولیه:** Function های Vercel بی‌حالت و گذرا هستند؛ شمارندهٔ
  in-memory بین فراخوانی‌های موازی یا بعد از cold start مشترک نیست، پس
  محدودسازی واقعی نرخ درخواست نمی‌دهد.
- **تصمیم نهایی مالک پروژه (۲۰۲۶-۱۱-۱۳):** ایمیل یک کانال فرعی و
  کم‌اهمیت است (مشتری واقعی مستقیم از `app.dofixo.ir/register` ثبت‌نام
  می‌کند)، پس ساخت یک فروشگاه خارجی پایدار فقط برای همین فرم، هزینه‌ای
  بیش از نیاز واقعی است. به‌جای آن فقط یک فیلد honeypot (در
  `src/pages/api/contact.ts` و هر دو فرم) اضافه شد. **اگر در آینده
  حجم اسپم واقعی دیده شود**، همین بند دوباره باز و یک فروشگاه خارجی
  (Vercel KV یا Redis) اضافه می‌شود — نه زودتر.

## D8 — ردیابی منبع تبلیغ (UTM): اسکریپت سراسری در Layout، نه ویرایش تک‌تک لینک‌ها

- **وضعیت:** Approved و **اجراشده، فقط سمت لندینگ** (۲۰۲۶-۱۱-۱۳).
- **مشکل:** مالک پروژه در شبکه‌های اجتماعی مختلف تبلیغ می‌کند و می‌خواهد
  نرخ جذب مشتری هر کانال را مقایسه کند. ده‌ها لینک `app.dofixo.ir/register`

  جدید باید تکرار شود.
- **تصمیم:** یک اسکریپت واحد در `src/layouts/Layout.astro` (که همهٔ ۱۳
  صفحهٔ ریپو از آن استفاده می‌کنند) موقع لود صفحه: (۱) اگر `utm_source`
  و مشابه در URL بازدید باشند، آن‌ها را در `localStorage` با مهلت ۳۰ روزه

  قبلی (در همین ۳۰ روز) می‌خواند. (۲) این مقادیر را به href هر لینکی که
  با `https://app.dofixo.ir/register` شروع می‌شود، به‌صورت query string
  می‌چسباند — بدون نیاز به دست‌زدن به خودِ لینک‌ها.
- **استدلال:** یک نقطهٔ نگه‌داری به‌جای ده‌ها فایل؛ برای مقالهٔ جدیدی
  که بعداً نوشته شود هم خودکار کار می‌کند، چون به ساختار Layout وصل
  است، نه به تک‌تک صفحات.
- **محدودیت دانسته‌شده:** این فقط نیمهٔ لندینگ است. تا وقتی اپ
  (`app.dofixo.ir`, ریپوی `repair-system`) همین پارامترها را در لحظهٔ
  ثبت‌نام از URL نخواند و ذخیره نکند، هیچ گزارشی از «کدام کانال مشتری
  آورد» ساخته نمی‌شود — نگاه کنید به `roadmap.md` (T6.3، Blocked).
- **فایل:** `src/layouts/Layout.astro`.
